# Contributing

1. Create a focused branch.
2. Do not add DHS microdata, direct download links, row-level outputs, or research model artifacts.
3. Add or update tests with behavior changes.
4. Run `ruff check .` and `pytest` before opening a pull request.
5. Describe scientific as well as software consequences in the pull request.

Commit messages should use a simple type such as `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, or `ci:`.
